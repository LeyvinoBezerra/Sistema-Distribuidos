## 📄 Lista 2

### 1. Arquitetura distribuída
- Estrutura de interação entre componentes.  
- Objetivos: escalabilidade, tolerância a falhas.

### 2. Arquitetura de software
- Estilos (cliente/servidor, P2P, camadas).  
- Padrões (MVC, microserviços).

### 3. Estilos arquitetônicos
- Camadas, cliente/servidor, P2P, eventos, microserviços.

### 4. Cliente/Servidor 3 camadas
- Apresentação, lógica, dados.  
- Vantagens: modularidade. Limitação: sobrecarga.

### 5. P2P
- Descentralizado, escalável, tolerante a falhas.  
- Ex.: BitTorrent, blockchain.

### 6. P2P estruturada vs não estruturada
- Não estruturada: conexões aleatórias (Gnutella).  
- Estruturada: DHT, busca eficiente (BitTorrent, IPFS).

### 7. Comparação
- Cliente/Servidor: centralizado, fácil gerenciar.  
- P2P: distribuído, escalável, difícil gerenciar.

### 8. Distribuição de arquivos
- Arquitetura: P2P.  
- Melhor: estruturada (eficiência).

### 9. Sistema acadêmico
- Cliente/Servidor.  
- 3 camadas: UI, lógica, dados.

### 10. Sobrecarga
- Problema: centralização.  
- Estratégias: replicação, balanceamento.  
- P2P: distribui carga.

### 11. Verdadeiro/Falso
- 1 ❌, 2 ✅, 3 ❌, 4 ✅, 5 ❌, 6 ✅.

### 12. Situações
- Bancário → Cliente/Servidor.  
- Arquivos → P2P.  
- Web separada → 3 camadas.  
- Recursos próprios → P2P.

### 13. Comércio eletrônico
- Arquitetura: Cliente/Servidor distribuído.  
- Estilos: microserviços + eventos.  
- Justificativa: arquitetura = organização geral; estilo = organização interna.
